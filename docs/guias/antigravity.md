# Antigravity

Este guia é para quando você quer usar a fábrica pelo Antigravity CLI (`agy`) em vez do Claude Code. A fábrica é um plugin do Claude Code, e o `agy plugin install <clone-da-fábrica>` converte skills, agentes e hooks para o formato dele. O resultado da conversão depende das versões dos dois lados: este guia registra o que foi testado com o **plugin 0.38.0** e o **`agy` 1.5.10**, em 2026-11-18, numa VM do `sbx` com modelo real (fase 0 em [#149](https://github.com/ftenorio99/fabrica/issues/149), pontos restantes em [#162](https://github.com/ftenorio99/fabrica/issues/162)). O registro do subagente `revisor` foi testado com o **plugin 0.42.0** e o `agy` 1.5.10 no host e 1.5.11 na VM do `sbx` ([#177](https://github.com/ftenorio99/fabrica/issues/177)).

## O que funciona
- **Instalação:** `agy plugin install` converte as 13 skills (comandos `/fabrica:*`), o agente `revisor` e os hooks `PreToolUse` e `SessionStart`.
- **Orquestração no `/fabrica:avancar`:** com `FABRICA_HARNESS=antigravity`, o `/fabrica:avancar` usa `run_workflow` para rodar issues independentes em paralelo (`parallel`) e cada issue em estágios isolados (`triagem` → `spec` → `implementar` → `revisar`). `implementar` e `revisar` rodam em estágios consecutivos (para o `revisar` poder chamar o subagente `revisor` sem exceder a profundidade de subagentes), com teto inclusivo de 4 etapas por execução, lock `em-andamento` garantido por `try/finally` e isolamento por worktree (`issue-worktree.sh`, `workspace="inherit"`). O `/swarm` não é disparado automaticamente; fica disponível como opção manual quando você inicia a sessão com `/swarm` para lotes amplos de issues, com um worker dedicado de revisão/verificação.
- **Proteções:** os hooks de proteção (`protect-main.sh`, `protect-production.sh`) negam de verdade, também com `--dangerously-skip-permissions`.
- **Etapas:** os comandos `/fabrica:*` rodam em modo `-p` e recebem argumento (fase 0 da #149).
- **Perguntas ao usuário:** o equivalente ao `AskUserQuestion` é a ferramenta `ask_question`. Nas etapas que perguntam (`prd`, `setup`), a pergunta sai como chamada da ferramenta, não como texto solto.
- **Subagentes built-in (`research`, `browser`) e `Workspace`:** com `FABRICA_HARNESS=antigravity`, `triagem` e `spec` delegam exploração ampla de código ao subagente `research` (somente leitura, sem texto externo da issue no prompt), e `implementar`, `revisar` e `revisor` podem acionar `browser` (ou `/browser`) de forma opcional para verificações visuais e E2E quando disponível (sem bloquear ambientes headless). As etapas mantêm `Workspace="inherit"` porque o `scripts/issue-worktree.sh` já isola cada issue em `<clone>/.worktrees/<nº>` (ADR 0014), reservando `Workspace="share"` ou `"branch"` apenas para subagentes auxiliares temporários fora do fluxo padrão ou sessões explícitas de `/swarm`.
- **Subagentes por etapa em `agy-agents/`:** além do `revisor`, o plugin declara em `agents.json` os subagentes especializados `triador` (`agy-agents/triador.md`), `especificador` (`agy-agents/especificador.md`) e `implementador` (`agy-agents/implementador.md`), com `tools`, `skills`, `model: inherit` e `commandExecutionPolicy: auto`. No `/fabrica:avancar`, o `run_workflow` usa cada subagente pelo `type_name` da etapa (com fallback `"self"`). Como `implementar` e `revisar` rodam como estágios consecutivos no `pipeline` do `run_workflow`, o fluxo automático não depende de `EnableSubagentTools: true`; o uso de `EnableSubagentTools` via `define_subagent` fica restrito a eventual invocação dinâmica fora do `run_workflow`.
- **Subagente `revisor`:** o `agy` registra o revisor instalado pelo plugin como subagente, e o `revisar` o chama pelo `invoke_subagent`, com o nome `revisor`. O `agy` lê o revisor de `agy-agents/revisor.md`, declarado no `agents.json` da raiz, e o Claude Code e o OpenCode, de `agents/revisor.md`. Os dois arquivos têm o mesmo corpo e mudam só o frontmatter: o `agy` exige `tools` em lista e com os nomes dele (`read_file`, `run_command`, `manage_task`), e recusa os do Claude Code (`Read`, `Bash`) ao montar o subagente. O `bash scripts/test-revisor-agent.sh` confere que os corpos são iguais: ao mudar o revisor, mude os dois. Por ser subagente (`mainAgent: false`), `agy --agent revisor` segue recusado, e o `agy agents` não o lista (no teste, a lista veio vazia). O `/agents` interativo também mostra só o agente `default`: ele lista agentes principais de sessão, e o revisor é subagente. Os subagentes aparecem para o modelo, que os chama pelo `invoke_subagent`; `agy plugin list` mostra `4 agents` para o plugin.
- **Revisão automática:** se o revisor não estiver disponível, o `revisar` cai no fallback — um subagente genérico registrado com o conteúdo de `agents/revisor.md` (via `define_subagent`). No teste da #162, ele devolveu a tabela de critérios de aceite com evidência e recusou um pedido de alterar arquivo, mantendo o repositório intacto.
- **Aviso do `SessionStart`:** o hook `hooks/session-start.sh` responde no contrato de quem o chamou. Sob o `agy`, o aviso de hooks do git ausentes sai como `{"injectSteps":[{"systemMessage":{...}}]}`, o formato que a documentação de hooks do `agy` 1.5.10 define para o `SessionStart`; sob o Claude Code, continua texto puro. O teste unitário (`bash scripts/test-session-start.sh`) cobre os dois contratos. A confirmação com o `agy` em uma VM do `sbx` (o modelo relatar o aviso e o log sem erro de parsing) ainda não foi feita: segue na [#178](https://github.com/ftenorio99/fabrica/issues/178).

## O que funciona com ressalva
- **Modelo das etapas:** o `/fabrica:avancar` detecta a harness antes do binário. Com `FABRICA_HARNESS=antigravity` no ambiente do `agy`, as etapas do `run_workflow` e a chamada ao `revisor` no `/fabrica:revisar` traduzem as labels `modelo:*` para os tiers do `agy` via `scripts/stage-model.sh agy-tier` (`haiku` → `flash_lite`, `sonnet` → `flash`, `opus` → `pro`, com fallback `inherit`), sem `claude -p` e sem escalonamento automático. Sem `FABRICA_HARNESS=antigravity`, o Antigravity ainda cai no caminho do binário `claude`; o sinal automático fica com a [#220](https://github.com/ftenorio99/fabrica/issues/220).
- **Modo `-p` não espera resposta:** o `ask_question` retorna imediatamente com resposta vazia (`A1:`), sem bloquear. Cabe ao modelo parar ou seguir; no teste, com instrução explícita de parar na primeira pergunta, ele parou sem responder por conta própria. Em sessão interativa, a pergunta chega ao usuário normalmente.
- **Restrição de ferramentas do revisor:** no `agy`, o revisor registrado não tem as ferramentas de editar e criar arquivos (`edit_file`, `write_file`): no teste, ele listou só `read_file`, `run_command`, `manage_task` e `send_message`, e recusou um pedido de editar arquivo, com o repositório intacto. O shell (`run_command`) fica liberado, como o `Bash` no Claude Code — o `agy` não oferece shell somente leitura —, e a regra de não alterar arquivos pelo shell vem das instruções do agente. No fallback do `define_subagent`, nem essa restrição existe: o shell vem atrelado a `EnableWriteTools`, junto com as ferramentas de editar.
